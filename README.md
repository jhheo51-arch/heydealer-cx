# 헤이딜러 인증중고차, 구매 고객은 어디서 신뢰를 잃는가

헤이딜러 CX Operator(인증중고차) 지원을 위해 만든 개인 분석과 포트폴리오입니다. 공개 조사와 공개 리뷰로 구매 고객의 불만이 어디에 모이는지 찾고, CX Operator로서 무엇을 먼저 할지 정리했습니다.

- 포트폴리오(웹): https://jhheo51-arch.github.io/heydealer-cx/
- 포트폴리오(PDF 10쪽): [portfolio.pdf](portfolio.pdf)
- 분석 코드와 집계: [analysis/](analysis)

| 96.7% | 1~3점 452건 중 회사 답글이 달린 437건 | 탐색 표본 |

## 쪽별 핵심

### 3쪽. 팔 때 만족 1위, 살 때 만족 4위
- 처분 만족도는 헤이딜러 59%로 1위(전년보다 5%p 상승), 구입 만족도는 36%로 4위(15%p 하락)입니다. 구입 만족 1위는 K카 63%입니다.
- 광고의 세 약속(모든 차량 무사고, 1년 무료 보증, 단순변심 무료 환불)이 각각 어떤 순간에 시험받는지 리뷰 사례와 연결했습니다. 예를 들어 1년 무료 보증은 쇼크업소버 결함이 소모품이라 거절될 때 시험받습니다.

### 4쪽. 구매 고객의 불만은 인수 뒤, 정보와 연락에 모입니다
- 차를 사거나 사려는 고객 글 21건을 여정 단계로 나누면 차량 탐색 11건, 정보 확인 3건, 구매 결정 3건, 이상 발견 2건, 보증 문의 1건, 정비와 보상 1건입니다.
- 인수 뒤 사례 4건(몇 주 연락 없음, 상담 요청 끊김, 전화 불통, 답변 받음)을 나란히 놓고, 1년 케어로 수리비를 바로 받은 고객은 5점을 줬다는 점과 비교했습니다.

### 5쪽. 조건은 가장 좋지만, 고객이 놓치기 쉬운 지점이 있습니다

| 항목 | 헤이딜러 | K카 | 엔카 홈서비스 |
|---|---|---|---|
| 단순변심 환불 | 3일 무료, 3일째 오후 6시 마감 | 3일, 100% 환불(오래된 차 일부 제외) | 7일, 배송 뒤 탁송비와 이용료 부담 |
| 보증 | 1년 2만km 무료, 제외 항목은 앱에서 안내 | 유료 워런티 상품 | 공식 자료에서 확인 못 함 |
| 반납과 정비 | 탁송 중심, 정비 연결은 입사 후 확인 | 가까운 직영점에 반납 | 탁송으로 회수 |
| 상담 | 채팅, FAQ, 구매예약 뒤 1영업일 해피콜 | 직영점 | 엔카매니저 |

- CX Operator가 먼저 챙길 것 세 가지: 인수 당일 안내에 환불 마감을 날짜와 시각으로 적기, 구매예약 해피콜에서 보증 제외 항목 먼저 짚기, "다른 곳은 보증이 더 길다던데요"에 무료와 유료의 차이로 답하기.

### 6쪽. 결론보다 기준과 다음 연락을 먼저 알립니다
- 응대 순서: 접수, 기록 확인, 기준 대조, 전문가 연결, 고객 설명, 종결 확인.
- 케이스 A(쇼크업소버 결함, 소모품이라 거절)와 케이스 B(브레이크 수리 일부만 승인, 몇 주 연락 없음)마다 문제, 판단, 대응과 다음 개선을 적었습니다.
- 설명 예시: "보증 대상인지 확인하려고 정비 담당자에게 사진을 보내 두었습니다. 내일 오후 3시까지 결과와 근거 조항을 알려 드리겠습니다."
- 원칙: 판정은 기준과 전문가가, 설명과 다음 연락 약속은 CX Operator가 맡습니다.

### 7쪽. 문의가 다른 팀으로 넘어간 동안에도 고객 쪽은 비우지 않습니다
- 가설: 판단이 정비팀에 넘어가 있는 동안 고객에게 소식을 줄 담당자가 없어 연락이 끊깁니다.
- 접수, 기록 확인, 판단 대기, 결과 안내, 종결 확인의 5단계마다 고객이 겪은 일, CX Operator가 할 일, 정비팀과 상품화팀이 할 일, 알림 도구를 나눴습니다.
- 핵심 규칙: 첫 응답에 담당자와 다음 연락 시각을 알리고, 판단 전에도 약속한 시각에 먼저 연락하며, 7일 뒤 해결 여부를 확인합니다.

### 8쪽. 차를 받은 날, 환불 마감을 날짜와 시각으로 알려 드립니다
- 헤이딜러 공식 블로그 예시(13일 인수, 15일 오후 6시 마감)대로 인수일을 1일째로 세어 마감 시각을 계산합니다. 마감일이 주말이면 따로 표시합니다.
- 인수 당일, 다음 날 오전, 마감 당일 오전에 보낼 안내 문자 3개를 만들고, 모든 문자에 결론, 근거, 다음 연락을 넣었습니다.

### 9쪽. 고객 손해의 크기로 순서를 정하고, AI와 일을 나눕니다

| 순서 | 과제 | 근거 | 첫 지표 |
|---|---|---|---|
| 1 | 수리 진행 중 건의 연락 약속 | 4건 중 3건 연락 끊김 | 약속 시각 안에 먼저 연락한 비율 |
| 2 | 보증 제외 항목의 구매 전 안내 | 리뷰 2건 | 거절로 끝난 보증 문의의 재문의율 |
| 3 | 점검 범위를 고객 말로 공개 | 리뷰 2건 | 인수 30일 안의 상태 이의 건수 |
| 4 | 부정 리뷰 뒤 재연락 | 답글만 달린 96.7% | 7일 안 재연락 비율 |

- AI는 연락 약속 찾기, 약관과 FAQ로 답변 초안 쓰기, 시간 외 환불 문의 분류, 주간 VOC 분류를 맡고, 사람은 먼저 연락하고 정비 소견과 맞추고 표본을 확인합니다.
- 원칙: 보증 판정, 환불 승인, 보상 금액은 AI가 정하지 않습니다.

### 10쪽. 같은 일이 다시 생기지 않게 만드는 사람입니다
- 실제 경험: 기록 대조로 못 받은 수당 400만 원을 찾아 두 번 거절 뒤 2주 만에 9명에게 지급, ARVIS 도입 뒤 직접 만드는 반복 서류를 월 40건에서 약 10건으로 줄임.
- 개인 프로젝트: [claim-relay](https://jhheo51-arch.github.io/claim-relay/web), [VoC Lens](https://voc-lens.streamlit.app).
- 3개월 계획: 1개월에 보증 기준과 점검표, 정비 용어를 익히고, 2개월에 연락 공백을 주간 VOC로 정리하고, 3개월에 환불 마감과 보증 제외 항목을 인수 당일 안내에 넣는 안을 상품화팀, 정비팀과 만듭니다.

## 왜 봤는가

컨슈머인사이트 2025년 조사에서 헤이딜러는 중고차 처분 만족 59%로 1위였지만, 구입 만족은 36%로 4위였고 전년보다 15%p 떨어졌습니다. 같은 브랜드에서 파는 고객과 사는 고객의 경험이 왜 갈리는지 공개 리뷰로 확인해 보려 했습니다.

## 무엇을 했는가

| 단계 | 내용 |
|---|---|
| 수집 | Google Play 리뷰 6,000건, 2024-03-21 ~ 2026-11-02, 최신순 (`analysis/collect.py`) |
| 1차 분류 | 1~3점 452건에 키워드 규칙으로 주제 1개 (`analysis/classify.py`) |
| 규칙 검증 | 규칙 결과 40건을 무작위로 직접 읽어 33건 일치. 틀린 7건은 광고나 앱 오류 글에 '딜러', '상담' 같은 단어가 섞인 경우 |
| 직접 분류 | 차를 사거나 사려는 고객의 글 21건(차를 받은 뒤 쓴 글 4건)을 전부 읽고 VOC 유형과 여정 단계를 붙임 |
| 정책 비교 | 헤이딜러 공식 블로그(2025.10), K카 보도자료, 엔카 이용 안내로 환불과 보증 조건 비교 |

## 무엇이 나왔는가

- 1~3점 452건 중 가장 많은 주제는 판매 가격과 감가(162건), 앱 오류와 속도(95건)였습니다. 차를 사거나 사려는 고객의 글은 21건이었고, 그중 차를 받은 뒤 쓴 글은 4건이었습니다.
- 21건 중 차량 탐색 단계가 11건으로 가장 많았습니다. 인수 뒤 보증과 수리 문제는 4건이었고, 그중 3건에 연락이 끊겼다는 내용이 함께 있었습니다. 4건은 비율로 말할 수 없는 수라서, 입사 후 상담 기록으로 확인할 가설로 둡니다.
- 452건 중 437건(96.7%)에 회사 답글이 달렸습니다. 답글 뒤 문제가 끝났는지는 리뷰로 알 수 없습니다.
- 1년 케어로 수리비를 바로 받았다는 5점 리뷰도 있어, 같은 보증 제도 안에서도 처리 과정에 따라 평가가 갈린다고 봤습니다.
- 정책 비교에서 헤이딜러는 1년 보증을 추가 비용 없이 주고, K카는 이를 유료 상품으로 둡니다. 다만 3일째 오후 6시 환불 마감과 보증 제외 항목은 고객이 놓치기 쉬워, 인수 당일 안내에 먼저 넣자고 제안했습니다.

집계는 [analysis/summary.json](analysis/summary.json), 건별 분류 결과는 [analysis/coded_low_no_text.csv](analysis/coded_low_no_text.csv)에 있습니다.

## 근거 표시

포트폴리오의 숫자 옆에는 근거를 세 가지로 표시했습니다.

- **공개 조사**: 언론 보도자료, 회사 공식 블로그와 이용 안내
- **탐색 표본**: 직접 수집해 분류한 앱 리뷰. 전체 고객의 비율이 아닙니다
- **가정**: 입사 후 확인할 부분. 문자 문안, 지표, 상담 도구, 주말 마감 처리 등

## 한계

- 앱 리뷰는 불만이 있는 사람이 더 많이 쓰므로 전체 고객의 비율이 아닙니다. 탐색 표본으로만 읽어야 합니다.
- 헤이딜러 내부 상담 데이터가 아닙니다. 개선 과제의 순서와 지표는 가설이며, 실제 상담 기록으로 다시 확인해야 합니다.
- 보증 제외 항목, 환불 기간 같은 세부 조건은 약관 원문으로 확인하지 않았습니다. 공식 블로그 글마다 보증 거리가 1만km와 2만km로 달라 입사 후 약관으로 확인합니다.
- 엔카의 보증 조건은 공식 자료에서 확인하지 못해 비교 표에 그대로 적었습니다.

## 데이터 원칙

리뷰 원문과 작성자 정보는 저장소에 올리지 않았습니다. CSV에는 리뷰 번호, 날짜, 별점, 답글 여부, 분류 결과만 있습니다. 직접 읽은 21건은 `classify.py` 안에 제 말로 요약한 한 줄만 남겼습니다.

## 다시 돌려 보기

```bash
pip install google-play-scraper
cd analysis
python collect.py    # 리뷰 6,000건 수집, heydealer_reviews.json (저장소에는 올리지 않음)
python classify.py   # 1~3점 분류, summary.json과 coded_low.csv 생성
```

리뷰는 최신순으로 수집하므로 실행하는 날에 따라 기간과 건수가 달라집니다.
